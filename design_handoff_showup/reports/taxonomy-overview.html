Sensitivity is inherited, then stampeddecision

The registry owns the classification; the client resolves it at emit time and writes it into the payload. Neither pure option works: fixing the class on the event would force one event per sensitivity level and destroy the generic attribute family, while a pure downstream join fails silently the moment the app ships a field the pipeline has not seen.

// detail_answered — gender
field_id:                 "gender"
value_bucketed:           "non_binary"
sensitivity_class:        2          // resolved from the registry, not joined downstream
field_registry_version:   "1.1.0"

// detail_answered — height, same event, different class
field_id:                 "height"
value_bucketed:           "175_179"
sensitivity_class:        0
1

The registry is the single source of truth, and it lives in the repo

One versioned file, compiled into both the client and the pipeline. Maintained in a spreadsheet, the two copies drift within a release.

2

Fail closed on an unknown field_id

Any identifier the pipeline does not recognise is treated as Class 2 until someone adds the registry row, and counted in an unclassified attributes metric. Wrong but safe, and visible — rather than special-category data landing in an unrestricted table and surfacing in an audit.

3

The stamp is historical truth

Reclassifying politics from 1 to 2 is a one-row edit, and rows collected beforehand still carry the class they were collected under. A downstream join cannot answer that, because it always returns today’s classification — and that is precisely the question a regulator asks.

4

Cost

One integer and one version string per event, plus the discipline of keeping the registry authoritative. Cheap against the alternative.

Legends

Sensitivity Class and Delivery Tier appear on all 266 rows of v1.0 and were defined nowhere. Classes 2 and 3 are new — previously every special-category field sat in Class 0 alongside device model.

Sensitivity class

Class 0
Operational. No personal meaning alone. Full warehouse access.
Class 1
Personal, not special-category. Consent states, coarse location, permissions, life circumstances. Access-controlled.
Class 2
Special-category, GDPR Art. 9 — gender, orientation, religion, politics, health and substance use. Bucketed on device; raw values never transmitted. Restricted role.
Class 3
Biometric or safety-critical. Result flags only, never the artefact. Named-individual access, audit-logged.
inherit
Class comes from the field_id registry and is stamped at emit time. Used by the generic attribute events.

Delivery tier

Tier 1
High-volume behavioural. Batched, best-effort, may be sampled. Loss tolerable.
Tier 2
Business-critical. Guaranteed delivery, retried, never sampled. Feeds funnels, score and billing.

Backend build statusnew

Live
Backend stores it. The event can fire and mean something today.
Partial
Stored, but not in the shape the event assumes.
Client only
Purely client-side by design — no backend counterpart expected.
Not built
No backend storage. Specified ahead of the build.

Conventions

Unchanged from v1.0 except where noted — recorded here because they were implicit.

Naming
object_action, past tense, lower snake case. An event names something that happened, never an intention.
Viewed vs shown
_viewed is user-initiated arrival; _shown is system-initiated presentation. The distinction is load-bearing for guard and gate modals.
Client vs server
Client fires intent and UI state; server fires the committed fact. Where both exist — date_confirm_submitted and date_confirmed — the server row is the one to count.
Free text is never sent
Only char_count, has_free_text or a bucket. This holds for prompts, bios, chat, reports and reviews without exception.
Bucketing happens on devicenew
A Class 2 value is bucketed before it leaves the client. The pipeline never receives a raw special-category string, so there is nothing to strip later.
Multi-select eventsnew
Fire once per change with a running total — interest_selected carries total_selected — never one event per final set.
