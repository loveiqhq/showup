1

screen_name: "<Flow> - <Screen>", the flow prefix taken from the epic and the screen in the words the ticket uses. Readable at a glance in a long analytics dropdown, and it sorts by flow.

2

screen_id: snake_case of the same words, prefixed by flow. Assigned once. If a screen is renamed, the label changes and the id does not.

3

One row per screen, not per state. A screen with ten states is one screen_id carrying a state property (see ConnectSSO).

4

A screen with no row has no ticket. If the row is missing, add it here first — that is the step that stops an event name being invented.

5

The two embrace bridges are TWO screens, not two states of one — they sit at different points in the flow and carry different copy. They share a shell and a variant value set (§16); they do not share a screen_id. Added 9 Sep 2026, before the Profile 05 ticket was written.

6

A bridge screen is a screen but NOT a step. profile_embrace_build has a row here and deliberately has no row in §2 — firing profile_step_viewed on it would put a phantom step in the completion funnel.

7

ProfilePhotos is step 1 of a DIFFERENT group ("The real you"), not a fifth step of "The basics". Its step_index is 1 within that group; §2 also records that photos sits outside the Share-some-details progress bar. Two progress bars, two vocabularies — do not renumber one against the other.

8

The photos screen's PERMISSION states have no events yet. A card-shown / mode / granted / refused / returned-from-settings set must be defined in events.json (with a closed access_status value set here) BEFORE the Profile 06 sprint — flagged 9 Sep 2026. Until then the screen's most likely drop-off point is invisible.

9

Profile 06 requests NO library permission (system picker on iOS and Android 13+), so the library access card is Android ≤ 12 only and there is no limited-access state at all. Any access_status value set defined later must cover the CAMERA (both platforms, always) and the old-Android library case — not an iOS library status, which we never read.

prompt length_bucket

5 values

Bucketed answer length on prompt_saved, and draft length on prompt_editor_dismissed (which adds "0" for an untouched field). NEVER SEND THE ANSWER TEXT — it is user-written free text about themselves, destined for a public profile, and it has no business in the analytics pipeline. The buckets exist to answer one question: did framing the field with a floor (“One good sentence is enough”) instead of a 0/160 ceiling move what people write. THE CANONICAL SHEET-CLOSE VOCABULARY, and the only one: every bottom sheet in the product reports its dismissal with these four values. Carried by prompt_editor_dismissed, prompt_topic_list_dismissed and media_prompt_list_dismissed, and by every sheet added after them. close is the X or a Cancel control; backdrop is a tap on the scrim; swipe is the drag-down gesture; system_back is the Android gesture or hardware key, which is NOT the same act as the X and must not be folded into it (decision 32). Created 16 Sep 2026 by unifying three drifted spellings of the same four acts — close|scrim|swipe|back on the prompts write sheet and cancel|backdrop|swipe|system_back on the media prompt list. Neither had shipped, so nothing in the warehouse needed migrating; a sheet-close value outside this set is a bug at the call site. Never use the key method for this (§8): method already means phone · apple · google.
