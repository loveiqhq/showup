## Animations added

Restrained on purpose — three motions, each earning its place:

| Motion | Where | Spec |
|---|---|---|
| Card transition | host | slide ⅙ width in the direction of travel + fade, 320ms |
| Progress fill | shell | segment colour tween, 320ms — reads as progress, not a redraw |
| CTA press | shell | circle only to 0.94, spring — the label stays put |

All three collapse to zero when the device asks for reduced motion: Android reads
`Settings.Global.ANIMATOR_DURATION_SCALE`, iOS reads `accessibilityReduceMotion`.
No entrance or stagger animation — on a screen the user is reading, motion on the
text itself delays comprehension for no gain.

## Deliberately not done

**String extraction (finding 12).** Every headline and rule row is a *styled* string — an italic
phrase inside a sentence, a two-tone `rule — consequence` row. Splitting those into fragments to
fit `strings.xml` is the standard way to make a UI untranslatable: word order differs per language,
so a translator needs the whole sentence with its emphasis marked inline. The correct route is one
resource per sentence carrying inline `<i>` / `<b>`, read through Compose 1.7's
`AnnotatedString.fromHtml` (already on the classpath — BOM 2024.10.00). That is a deliberate
refactor with its own visual re-verification, not something to fold into a pixel-accuracy pass.
